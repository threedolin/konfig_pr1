# Эмулятор командной строки UNIX (вариант 18)

Практическая работа №1 по конфигурационному управлению.

## Общее описание

Консольное приложение на Python, которое имитирует работу командной строки
UNIX-подобной ОС. Сейчас реализованы этапы 1 и 2: REPL (программа выводит
приглашение, читает команды и выполняет их) и настройка через параметры
командной строки со стартовым скриптом. Команды `ls` и `cd` пока
являются заглушками.

Приглашение строится из реальных данных ОС (имя пользователя и имя хоста),
например: `gagik@debian:~$`.

Структура:

- `src/shell.py` — парсер и класс эмулятора
- `src/main.py` — точка входа
- `tests/test_shell.py` — тесты
- `tests/scripts/` — стартовые скрипты и скрипты ОС для проверки параметров
- `run.sh` — скрипт запуска

## Функции и настройки

### Параметры командной строки

```
./run.sh [--vfs ПУТЬ] [--script ПУТЬ]
```

- `--vfs` — путь к физическому расположению VFS (пока только выводится,
  VFS появится на этапе 3);
- `--script` — путь к стартовому скрипту;
- `-h`, `--help` — справка.

При запуске выводятся все параметры (отладочный вывод):

```
[debug] Параметры запуска:
[debug]   vfs    = /home/user/my_vfs
[debug]   script = None
```

### Стартовый скрипт

Текстовый файл с командами эмулятора, по одной в строке. Команды
выполняются по порядку, каждая выводится вместе с приглашением и
результатом — как будто ее ввел пользователь.

- если в строке ошибка, выводится сообщение об ошибке и
  `[script] строка N с ошибкой пропущена`, выполнение продолжается;
- пустые строки и строки, начинающиеся с `#`, пропускаются;
- `exit` в скрипте завершает работу эмулятора;
- после скрипта эмулятор переходит в обычный интерактивный режим;
- если файл скрипта не найден, выводится ошибка.

### Парсер и команды

Парсер разбивает строку на команду и аргументы по пробелам. Текст в
кавычках (`"..."` или `'...'`) считается одним аргументом, например
`cd "my folder"`. Если кавычка не закрыта, выводится ошибка.

Команды:

| Команда | Что делает |
|---------|------------|
| `ls [аргументы]` | заглушка, выводит имя команды и аргументы |
| `cd [путь]` | заглушка, выводит имя команды и аргумент (больше одного аргумента — ошибка) |
| `exit` | выход из эмулятора |

Ошибки, которые обрабатываются:

- неизвестная команда;
- неверные аргументы (`cd a b`, `exit 1`);
- незакрытая кавычка.

Выйти также можно через `Ctrl+D` или `Ctrl+C`.

## Сборка и запуск тестов

Нужен Python 3.8+, сторонние библиотеки не используются, сборка не нужна.

Запуск:

```
./run.sh
```

Тесты:

```
PYTHONPATH=src python3 -m unittest discover tests
```

`PYTHONPATH=src` нужен, чтобы тесты нашли модуль `shell` из папки `src`.

Скрипты ОС для проверки параметров командной строки (`tests/scripts/`):

- `test_no_params.sh` — запуск без параметров;
- `test_vfs.sh` — только `--vfs`;
- `test_script.sh` — только `--script`: скрипт без ошибок, с ошибками,
  несуществующий файл;
- `test_all_params.sh` — оба параметра, `--help`, неверный параметр.

Запуск, например: `sh tests/scripts/test_script.sh`.

## Примеры использования

```
$ ./run.sh
gagik@debian:~$ ls
ls, аргументы: []
gagik@debian:~$ ls -l "my documents"
ls, аргументы: ['-l', 'my documents']
gagik@debian:~$ cd 'new folder'
cd, аргументы: ['new folder']
gagik@debian:~$ cd a b
Ошибка: cd: слишком много аргументов
gagik@debian:~$ hello
Ошибка: неизвестная команда 'hello'
gagik@debian:~$ ls "abc
Ошибка: не закрыта кавычка "
gagik@debian:~$ exit 1
Ошибка: exit: команда не принимает аргументы
gagik@debian:~$ exit
```

Запуск со стартовым скриптом, в котором есть ошибки:

```
$ ./run.sh --script tests/scripts/start_errors.txt
[debug] Параметры запуска:
[debug]   vfs    = None
[debug]   script = tests/scripts/start_errors.txt
gagik@debian:~$ ls first
ls, аргументы: ['first']
gagik@debian:~$ hello world
Ошибка: неизвестная команда 'hello'
[script] строка 3 с ошибкой пропущена
gagik@debian:~$ cd a b
Ошибка: cd: слишком много аргументов
[script] строка 4 с ошибкой пропущена
gagik@debian:~$ ls "abc
Ошибка: не закрыта кавычка "
[script] строка 5 с ошибкой пропущена
gagik@debian:~$ ls after_errors
ls, аргументы: ['after_errors']
gagik@debian:~$ exit
```
