# Эмулятор командной строки UNIX (вариант 18)

Практическая работа №1 по конфигурационному управлению.

## Общее описание

Консольное приложение на Python, которое имитирует работу командной строки
UNIX-подобной ОС. Реализованы все 5 этапов: REPL (программа выводит
приглашение, читает команды и выполняет их), настройка через параметры
командной строки со стартовым скриптом, загрузка виртуальной файловой
системы (VFS) в память, основные команды `ls`, `cd`, `uname`, `who`, `wc`
и команды `rm`, `chown`, которые изменяют VFS (только в памяти).

Приглашение строится из реальных данных ОС (имя пользователя и имя хоста),
например: `gagik@debian:~$`.

Структура:

- `src/shell.py` — парсер и класс эмулятора
- `src/commands.py` — команды `ls`, `cd`, `uname`, `who`, `wc`, `rm`, `chown`
- `src/vfs.py` — загрузка VFS в память и работа с путями
- `src/main.py` — точка входа
- `tests/test_*.py` — тесты
- `tests/scripts/` — стартовые скрипты и скрипты ОС
- `tests/vfs/` — тестовые VFS: `minimal`, `several`, `deep`
- `run.sh` — скрипт запуска

## Функции и настройки

### Параметры командной строки

```
./run.sh [--vfs ПУТЬ] [--script ПУТЬ]
```

- `--vfs` — путь к директории, из которой загружается VFS;
- `--script` — путь к стартовому скрипту;
- `-h`, `--help` — справка.

При запуске выводятся все параметры (отладочный вывод):

```
[debug] Параметры запуска:
[debug]   vfs    = tests/vfs/several
[debug]   script = None
```

### Виртуальная файловая система (VFS)

Источник VFS — директория на диске. При запуске она целиком (все папки и
содержимое файлов) читается в память, в словари Python:

- папка — `{"type": "dir", "children": {имя: элемент, ...}, "owner": ..., "group": ...}`;
- файл — `{"type": "file", "content": b"...", "owner": ..., "group": ...}`.

Владелец и группа берутся из реальных файлов на диске.

Дальше эмулятор работает только с копией в памяти, файлы на диске не
изменяются. Символические ссылки при загрузке пропускаются.

После загрузки выводится отладочная строка:

```
[debug] VFS 'deep' загружена в память: папок - 9, файлов - 7
```

Если `--vfs` не задан, используется пустая VFS `default`.

Ошибки загрузки VFS (эмулятор завершается с кодом 1):

- путь не найден — `Ошибка: не удалось загрузить VFS: путь к VFS не найден`;
- указан файл, а не директория — `... неверный формат VFS, нужна директория`;
- нет прав на чтение папки или файла.

### Стартовый скрипт

Текстовый файл с командами эмулятора, по одной в строке. Команды
выполняются по порядку, каждая выводится вместе с приглашением и
результатом — как будто ее ввел пользователь.

- если в строке ошибка, выводится сообщение об ошибке и
  `[script] строка N с ошибкой пропущена`, выполнение продолжается;
- пустые строки и строки, начинающиеся с `#`, пропускаются;
- `exit` в скрипте завершает работу эмулятора;
- после скрипта эмулятор переходит в обычный интерактивный режим;
- если файл скрипта не найден, выводится ошибка.

### Парсер и команды

Парсер разбивает строку на команду и аргументы по пробелам. Текст в
кавычках (`"..."` или `'...'`) считается одним аргументом, например
`cd "my folder"`. Если кавычка не закрыта, выводится ошибка.

Корень VFS считается домашней папкой: в приглашении он показывается как
`~`, вложенные папки — как `~/home/user`. В путях можно использовать
`/` (корень VFS), `~`, `.` и `..`, абсолютные и относительные пути.

Команды:

| Команда | Что делает |
|---------|------------|
| `ls [-l] [путь ...]` | содержимое папки (без пути — текущей). `-l` — подробно: тип (`d` — папка, `-` — файл), владелец, группа, размер, имя. Для файла выводится его имя, для нескольких папок — заголовки `путь:` |
| `cd [путь]` | переход в папку. Без аргументов или `~` — в корень VFS |
| `uname [-a] [-s] [-n] [-r] [-m]` | данные реальной ОС: `-s` имя ядра (по умолчанию), `-n` имя компьютера, `-r` версия ядра, `-m` архитектура, `-a` всё сразу |
| `who [-H]` | пользователь, терминал и время входа (время запуска эмулятора). `-H` — заголовок |
| `wc [-l] [-w] [-c] файл ...` | число строк, слов и байтов (без флагов — всё). Для нескольких файлов — строка `total` |
| `rm [-r] [-f] путь ...` | удаляет файлы. `-r` — удалять папки вместе с содержимым, `-f` — не выводить ошибку для несуществующих файлов. Нельзя удалить `.`, `..` и корень VFS. Если удалена текущая папка, эмулятор переходит в папку выше |
| `chown [-R] владелец[:группа] путь ...` | меняет владельца и группу. `chown :группа путь` — только группу, `-R` — у папки и всего содержимого. Пользователь и группа должны существовать в реальной ОС. Результат виден в `ls -l` |
| `exit` | выход из эмулятора |

Команды `rm` и `chown` меняют только VFS в памяти — файлы на диске не
удаляются и не меняют владельца.

Флаги можно писать вместе: `ls -l`, `uname -nm`.

Ошибки, которые обрабатываются:

- неизвестная команда;
- неверные аргументы (`cd a b`, `exit 1`, `uname x`, `who x`);
- неверный флаг (`ls -z`, `wc -x`);
- путь не найден (`ls nope`, `cd nope`, `wc nope`);
- папка вместо файла и наоборот (`cd etc/passwd`, `wc etc`, `rm var`);
- запрещенное удаление (`rm -r .`, `rm -r ~`);
- несуществующий пользователь или группа (`chown no_user etc`);
- незакрытая кавычка.

Выйти также можно через `Ctrl+D` или `Ctrl+C`.

## Сборка и запуск тестов

Нужен Python 3.8+, сторонние библиотеки не используются, сборка не нужна.

Запуск:

```
./run.sh
```

Тесты:

```
PYTHONPATH=src python3 -m unittest discover tests
```

`PYTHONPATH=src` нужен, чтобы тесты нашли модуль `shell` из папки `src`.

Скрипты ОС для проверки параметров командной строки (`tests/scripts/`):

- `test_no_params.sh` — запуск без параметров;
- `test_vfs.sh` — только `--vfs`;
- `test_script.sh` — только `--script`: скрипт без ошибок, с ошибками,
  несуществующий файл;
- `test_all_params.sh` — оба параметра, `--help`, неверный параметр.

Скрипты ОС для проверки разных VFS (этап 3), все запускают стартовый
скрипт `tests/scripts/start_stage3.txt` с командами и ошибками:

- `test_vfs_minimal.sh` — минимальная VFS (один файл);
- `test_vfs_several.sh` — несколько файлов;
- `test_vfs_deep.sh` — 4 уровня вложенности папок;
- `test_vfs_errors.sh` — несуществующий путь, файл вместо папки, VFS по
  умолчанию.

Этап 4: `test_stage4.sh` запускает стартовый скрипт
`tests/scripts/start_stage4.txt` со всеми режимами `ls`, `cd`, `uname`,
`who`, `wc` и их ошибками на VFS `deep`.

Этап 5: `test_stage5.sh` запускает `tests/scripts/start_stage5.txt` со
всеми режимами `rm` и `chown` и их ошибками, а после работы эмулятора
проверяет, что файлы VFS на диске не изменились.

Запуск, например: `sh tests/scripts/test_stage5.sh`.
